{% comment %} SPDX-FileCopyrightText: 2026 Jonas Huber © Reiner Lemoine Institut SPDX-License-Identifier: AGPL-3.0-or-later A list tab's results region (login.list_views.ListTabView): status segment, chips slot, table, pager. Every id, event and URL comes from ``frame`` and every noun from ``page.listing``, so nothing here names what is listed. A direct load and an htmx request render this same state; htmx gets only this. Every control carries a stable id, so focus can be put back by id after a swap. ``data-announce`` is what the persistent live region outside reads after the swap; ``data-filters`` is what each filter keeps in the URL, ``data-more`` how many filters behind "More filters" apply and ``data-folded`` how many behind "Filters (n)", so the bar outside can follow a change made in here (a chip removed, a Reset). The columns collapse by the list's own width, not the viewport's: the tab's container queries hide a column by its cell class, and on the narrowest lists stack each row into two lines and show the "Sort by" select in place of the column headers. Every cell therefore carries its column's class. Selecting: a checkbox per row, labelled with the row's title and carrying ``row.name``, and a tri-state one in the header for the page. Where the rows stack and the header row is hidden, "Select this page" in the bar above is that same tri-state box (#2596). The selection itself is the browser's, a list of names in page memory; the region only says which scope it shows (``data-scope``, its filters without sort and page: another scope clears the selection) and where the names of every matching item come from (the banner's ``data-names-url``). The banner offers "Select all N matching" once the whole page is ticked; the tab's module shows it and picks its wording. After an action the region re-fetches itself with the state it shows (``-changed``, sent by the action's response). The request names the region as its trigger, so the view answers with HX-Replace-Url: an action adds no history entry. A row offers ``key`` (what its ids are built from), ``name`` (what a selection and an action carry) and ``title``. Blocks: ``empty`` (the account has nothing yet), ``nomatch`` (nothing matches the filters; by default the listing's plural and Reset), ``head_cells`` and ``row_cells`` (every column after the selection box). The ids that are not per tab (``select-page``, ``row-``, ``nomatch-reset``, ...) stay unprefixed: a page holds one list. {% endcomment %}

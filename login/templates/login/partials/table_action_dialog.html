It shows the preflight: which Tables are left out and why, what the action needs (publish: Topic and embargo), and the consequences it has to state (unpublish: other people's Datasets that will hold a draft member; delete: the Datasets left, Review state, an active embargo and knowledge-graph links, counted for a batch). The Dataset actions choose one of the user's own Datasets first (table_action_dataset.html). Delete may ask for a typed confirmation (``preflight.confirmation``: the Table's name or the number of Tables; table_action_delete.html). Over the action's ceiling nothing can be confirmed. The form posts the eligible names only, so what runs is what was shown (as one comma-joined ``tables`` field). A refused request comes back here with ``notice`` ("Nothing was changed: …") and the preflight run again; an unusable parameter comes back with ``errors`` beside its field. Everything that depends on the chosen Dataset is in #table-action-preview (the left-out groups, the list, the names the form posts) and #table-action-footer (whether it can be confirmed), so a bulk Dataset dialog's re-check swaps those two and never the select the user is on. {% endcomment %} {% with check=preflight %}
